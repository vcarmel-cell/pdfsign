# PDFSign — מילוי טפסי PDF וחתימה דיגיטלית

אפליקציית דף-אינטרנט סטטית (בלי שרת, בלי build) שמאפשרת להעלות מסמכי PDF, לסמן עליהם היכן צריך למלא נתונים ולחתום, ולשלוח קישור לשותפים שממלאים וחותמים כל אחד עותק משלו.

- `admin.html` — ניהול: התחברות, העלאת תבניות, סימון שדות, קישורי שיתוף, צפייה בהגשות.
- `fill.html?id=...` — הדף שהשותפים פותחים כדי למלא ולחתום.

כל הלוגיקה רצה בדפדפן. Firebase (Firestore + Auth) משמש כאחסון משותף, ו-EmailJS שולח התראת מייל (כולל צירוף ה-PDF החתום) בכל הגשה — בלי Cloud Functions ובלי Firebase Storage, ולכן **בלי צורך בשדרוג לתוכנית בתשלום (Blaze)**.

**חשוב להבין:** מכיוון שאין Firebase Storage, קובצי ה-PDF (גם התבנית המקורית וגם כל מסמך חתום) נשמרים כמחרוזת Base64 בתוך מסמך Firestore עצמו. מסמך ב-Firestore מוגבל ל-1MB, ולכן **קובץ המקור מוגבל לכ-500KB**. זה מתאים מצוין לטפסים/חוזים מבוססי-טקסט (בדרך כלל עשרות עד מאות KB), אבל לא לסריקות/תמונות ברזולוציה גבוהה.

## הקמה (חד פעמי)

### 1. פרויקט Firebase חדש
ב-[console.firebase.google.com](https://console.firebase.google.com) → Add project → צרו פרויקט ייעודי חדש (לא לחבר לפרויקט קיים אחר בשימוש).

בתוך הפרויקט הפעילו:
- **Authentication** → Sign-in method → הפעילו **Email/Password** וגם **Anonymous**.
- **Firestore Database** → Create database → מצב Production.

אין צורך להפעיל Storage בכלל.

### 2. יצירת משתמש המנהל
Authentication → Users → Add user → הזינו `v.carmel@gmail.com` וסיסמה לבחירתכם. זהו חשבון המנהל היחיד; אין הרשמה עצמית באפליקציה.

### 3. חוקי אבטחה
Firestore → Rules → העתיקו לשם את תוכן הקובץ `firestore.rules` ולחצו Publish. (חוקי ה-Firestore כוללים גם בדיקת גודל על שדה ה-PDF, כדי שמסמך שחורג מהמכסה יידחה בצד השרת ולא רק בצד הלקוח.)

### 4. חיבור האפליקציה לפרויקט
Project settings → General → Your apps → הוסיפו אפליקציית Web → העתיקו את אובייקט הקונפיג שמתקבל (`apiKey`, `authDomain` וכו') לתוך `js/firebase-init.js`, במקום הערכים ש-`PASTE_...` (את `storageBucket` אפשר להשאיר כמו שהוא, הוא פשוט לא בשימוש).

### 5. EmailJS (למייל התראה + צירוף ה-PDF החתום בכל הגשה)
1. הרשמו בחינם ב-[emailjs.com](https://www.emailjs.com).
2. Email Services → חברו שירות מייל (למשל Gmail) → קבלו **Service ID**.
3. Email Templates → צרו תבנית עם המשתנים: `{{template_name}}`, `{{filler_name}}`, `{{submitted_at}}`. **חשוב:** בהגדרות התבנית עצמה שדה "To Email" חייב להיות `{{to_email}}` — אחרת המייל לא יישלח לכתובת הדינמית ולא תופיע שגיאה.
4. באותה תבנית, עברו ללשונית **Attachments** → הוסיפו צירוף מסוג **Variable Attachment** → תנו לו את שם המשתנה `pdf_attachment` וסוג תוכן PDF. (המגבלה בתוכנית החינמית של EmailJS היא כ-500KB לצירוף — תואם בדיוק למגבלת הקובץ באפליקציה.)
5. קבלו **Template ID**, ומתחת ל-Account → General את ה-**Public Key**.
6. הזינו את שלושת הערכים ב-`js/firebase-init.js` תחת `EMAILJS_CONFIG`.

אם משאירים את `EMAILJS_CONFIG.publicKey` כ-`PASTE_...`, האפליקציה תמשיך לעבוד רגיל (הגשות נשמרות כרגיל ב-Firestore) — רק שליחת המייל תדולג בשקט.

### 6. בדיקה מקצה לקצה
1. פתחו את `admin.html`, התחברו.
2. העלו PDF קטן לדוגמה (מתחת ל-500KB), תנו לו שם.
3. בעורך השדות: בחרו סוג שדה (טקסט/תאריך/תיבת סימון/חתימה) וגררו מלבן על המסמך במקום הרצוי. שמרו שדות.
4. העתיקו את קישור השיתוף ופתחו אותו בטאב/דפדפן אחר (או בטלפון) כאילו אתם שותף.
5. מלאו את כל השדות, חתמו (עכבר או אצבע), שלחו.
6. חזרו ל-`admin.html` → "הגשות" → ודאו שההגשה מופיעה, שאפשר להוריד ממנה PDF, ושהוא מציג את הטקסט והחתימה בדיוק במקומות שסומנו. בדקו גם שהגיע מייל עם הקובץ מצורף.
7. פתחו את אותו קישור שיתוף בפעם נוספת כ"שותף אחר" — ודאו שנוצרת הגשה נפרדת נוספת (הקישור אינו חד-פעמי).

## תפקידים: מנהל ומשתמשים

יש שני סוגי חשבונות:
- **מנהל-על** — תמיד `v.carmel@gmail.com` (מוגדר קשיח בקוד ובחוקי האבטחה, לא ניתן לשינוי דרך הממשק). רואה ומנהל את **כל** התבניות וההגשות של כל המשתמשים, ובנוסף יכול ליצור/לבטל גישה למשתמשים דרך מסך "ניהול משתמשים" (מופיע רק אצלו).
- **משתמשים** — נוצרים ע"י המנהל (מסך "ניהול משתמשים" → אימייל + סיסמה זמנית). כל משתמש רואה ומנהל **רק** את התבניות וההגשות שהוא עצמו יצר, ויכול לשלוח קישורי מילוי ללקוחות שלו באופן עצמאי. אחרי הכניסה הראשונה, המשתמש יכול לשנות את הסיסמה הזמנית בעצמו (מסך "תבניות" → "שינוי סיסמה").

**"ביטול גישה" למשתמש לא מוחק את חשבון ה-Auth שלו** (אין ל-client-side גישה למחיקת חשבונות משתמשים אחרים בלי Admin SDK) — זה רק מסיר ממנו את ההרשאה להשתמש באפליקציה, באופן מיידי (גם אם הטאב שלו כבר פתוח). "הפעלה מחדש" מחזירה גישה לאותו חשבון בדיוק, בלי צורך ליצור אותו מחדש.

**חשוב לאחר השדרוג הראשון**: תבניות שנוצרו *לפני* הוספת מערכת המשתמשים לא היו שייכות לאף אחד באופן מפורש. בפעם הראשונה שהמנהל-על נכנס ל-`admin.html` אחרי השדרוג, האפליקציה "מאמצת" אוטומטית את כל התבניות הישנות האלה אליו (שיוך `ownerId`). **מומלץ להיכנס כמנהל פעם אחת מיד אחרי פרסום הגרסה הזו**, לפני שמישהו אחר מנסה למלא קישור לתבנית ישנה — אחרת מילוי טופס כזה עלול להיכשל עד שהמנהל יתחבר בפעם הראשונה.

## הערות טכניות

- תבנית PDF שהועלתה היא **בלתי ניתנת להחלפה** — כדי לעדכן מסמך יוצרים תבנית חדשה (כדי שמיקומי השדות, שנשמרים כאחוזים מגודל העמוד, לא "יזוזו" ביחס למסמך חדש).
- טקסט שהמשתתף מקליד (כולל עברית) מוטבע ב-PDF כתמונה שנוצרת בדפדפן (canvas), ולא כטקסט PDF רגיל — כך נמנעת בעיית קידוד גופנים בעברית מול הגופנים הסטנדרטיים של pdf-lib.
- אם המסמך החתום הסופי (אחרי הטבעת הטקסט והחתימה) חורג מהמכסה למרות שהתבנית המקורית הייתה בתוך הגבול, ההגשה עדיין נשמרת ב-Firestore (בלי עותק PDF), והמערכת מזהירה את השותף במסך ההצלחה להוריד עותק אישי מיד — כדי שלא יאבד.
- אין כלי בדיקות אוטומטיות בפרויקט הזה (כמו שאר התיקיות בסביבת העבודה) — הבדיקה היא ידנית לפי הצעדים בסעיף 6.
